# 제품 요구사항 (PRD)

- **상태**: 승인 완료 (2026-11-24)
- **프로젝트명**: `mini-corebank` (원화 계좌·송금 코어뱅킹 원장 시스템)
- **한 줄 소개**: 1금융권(시중은행) 코어뱅킹의 핵심 원리인 복식부기 원장, 동시성·멱등성 이체, 정합성 대사, 보안·감사 로그를 검증 가능한 테스트와 간단한 웹 데모로 구현한 원화 계좌·송금 백엔드 포트폴리오.
- **대상 사용자**:
  - **일반 고객(데모 사용자)**: 계좌 개설, 입출금, 즉시/예약 이체, 거래내역 조회를 수행하는 사용자
  - **운영/감사자(관리 화면)**: 계좌 거래정지 해제, 원장-잔액 정합성 대사(Reconciliation) 실행, 감사 로그 확인
  - **채용 담당자/면접관**: 코드·테스트·데모 화면을 통해 금융 도메인 백엔드 역량을 검증하는 리뷰어

---

## 핵심 기능 (MVP)

안정적인 완성을 위해 **마일스톤 1(코어 원장) → 마일스톤 2(1금융권 심화) → 마일스톤 3(웹 데모 & 마무리)** 순으로 단계적 구현한다.

### 마일스톤 1 — 코어 계좌·복식부기 원장·안전한 이체
1. **회원가입 · 로그인 · 권한 제어**
   - 사용자 인증 및 본인 계좌만 조회/출금 가능한 소유권 검증
2. **계좌 관리**
   - 원화(KRW) 입출금 계좌 개설, 계좌번호 발급, 잔액·계좌 목록 조회
   - 계좌 상태 관리: `ACTIVE`(정상), `LOCKED`(거래정지), `CLOSED`(해지)
3. **복식부기 원장(Double-Entry Ledger) 기반 입금 · 출금 · 즉시 이체**
   - 모든 금전 이동은 원장 분개(차변/대변 합계 일치)로 기록하며, 외부 입·출금은 시스템 시재(Vault) 계정을 상대 계정으로 사용해 대차 평균을 유지
   - 금액은 `BigDecimal` 또는 원 단위 정수(64-bit)만 사용 (`float`/`double` 금지)
   - **동시성 제어**: 동일 계좌 동시 출금/이체 시 잔액 정합성 보장, 상호 이체 시 데드락 방지(계좌 ID 정렬 락 등)
   - **멱등성(Idempotency)**: `Idempotency-Key` 기반으로 네트워크 재시도·중복 요청 시 이중 출금/이체 방지
   - **한도 검증**: 1회 이체 한도 및 1일 누적 이체 한도 체크
4. **거래내역 조회 & 감사 로그(Audit Log)**
   - 계좌별 거래내역(기간/유형 필터, 페이징)
   - 모든 금전 거래 및 주요 보안 이벤트(로그인, PIN 오류, 계좌 잠금 등)에 대해 누가·언제·무엇을·결과를 감사 로그로 기록
   - 로그 내 민감정보(비밀번호, PIN, 계좌번호 전체 등) 마스킹

### 마일스톤 2 — 1금융권 실무 심화 기능
5. **계좌 비밀번호(PIN) 검증 & 오류 횟수 잠금**
   - 출금·즉시 이체·예약 이체 등록 시 계좌 PIN 검증(해시 저장)
   - 연속 5회 오류 시 계좌 상태를 `LOCKED`(거래정지)로 자동 전환하고 감사 로그 기록 (운영자 해제 기능 포함)
6. **원장-잔액 정합성 대사(Reconciliation)**
   - 전체 계좌의 현재 잔액과 원장 분개 합계의 일치 여부, 거래별 차변/대변 합계 일치 여부를 점검하는 대사 배치/수동 실행 기능
   - 대사 결과 이력(실행 시각, 검사 계좌 수, 불일치 건수 및 상세) 저장 및 조회
7. **예약 이체(Scheduled Transfer)**
   - 지정 시각에 실행될 예약 이체 등록(등록 시 PIN 검증), 조회, 취소
   - 스케줄러가 도래 건을 멱등하게 처리하며, 실행 시점에 계좌 상태·잔액·한도를 재검증해 성공/실패 및 실패 사유를 기록

### 마일스톤 3 — 데모용 최소 웹 화면 & 포트폴리오 마무리
8. **간단한 웹 데모 화면**
   - 백엔드 동작을 시연하기 위한 최소 기능 UI: 로그인/회원가입, 내 계좌 목록·개설, 입출금·즉시 이체(PIN 입력)·예약 이체, 거래내역 조회, 운영자 대사 실행/결과 및 감사 로그 조회
   - 디자인 고도화보다 기능 시연과 명확한 상태/에러 표시에 집중

## 하지 않을 것 (MVP 제외 범위)

- 실제 금융망 연동 (오픈뱅킹, 펌뱅킹, 금융결제원)
- 실명인증 / 본인인증(PASS·휴대폰 인증), KYC
- 외화 계좌, 환율 계산, 해외 송금 (원화 KRW 전용)
- 이자 계산, 예·적금, 대출 상품
- 복잡한 프론트엔드 디자인 시스템, 모바일 반응형 최적화
- 실제 운영 배포용 대규모 분산 인프라(멀티 리전, Kafka 클러스터 등 — 단일 DB 트랜잭션·정합성에 집중)

## 포트폴리오에서 보여주고 싶은 역량 (1금융권 백엔드 핵심)

1. **금융 데이터 무결성**: 복식부기 원장 설계, 정수/BigDecimal 금액 처리, 원장-잔액 정합성 대사(Reconciliation)
2. **동시성·트랜잭션·멱등성**: Race Condition·Lost Update·데드락 방지, `Idempotency-Key` 기반 중복 이체 차단, 예약 이체 중복 실행 방지
3. **은행 도메인 규칙 & 상태 관리**: 계좌 상태 전이(`ACTIVE`/`LOCKED`/`CLOSED`), 1회/1일 한도, PIN 5회 오류 잠금
4. **보안·감사·운영 관점**: 인증/인가(소유권 검증), PIN 해시 저장, 감사 로그, 민감정보 마스킹, 표준화된 도메인 예외 코드
5. **테스트로 증명하는 신뢰성**: 경계값(0원/음수/잔액 부족/한도 초과), 멀티스레드 동시성 테스트, 중복 요청 테스트, 정합성 대사 검증 테스트

---

## 승인 전 확인 메모 (리스크 점검)

- **범위 관리**: 3개 심화 기능(PIN 잠금, 정합성 대사, 예약 이체)을 모두 포함하되, 마일스톤 1(코어 원장)을 먼저 테스트까지 완결한 뒤 마일스톤 2로 넘어가는 방식으로 품질 저하를 방지합니다.
- **프론트엔드 비중**: 백엔드 포지션 포트폴리오이므로 UI는 백엔드 시연에 필요한 최소 수준으로 제한합니다.
