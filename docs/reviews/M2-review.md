# 마일스톤 2 코드 리뷰

검토 범위: PIN 잠금/해제, 원장-잔액 대사, 예약 이체 및 스케줄러

## 요약

- CRITICAL: 0
- HIGH: 0
- MEDIUM: 2
- LOW: 1

세 기능은 본 거래 롤백과 보안/운영 상태 커밋을 분리했고, 대사는 스냅샷 집계와 상세 상한을 도입했으며, 예약 이체는 행 락과 내부 멱등키를 사용했다.

## 발견 이슈

### [RV-M2-01] 대사 스케줄러 다중 인스턴스 중복 실행

- **심각도:** MEDIUM
- **위치:** `ReconciliationScheduler.java`, `@Scheduled`
- **위험 시나리오:** 여러 애플리케이션 인스턴스가 실행되면 매일 같은 시각에 중복 대사 이력이 생길 수 있다.
- **권장 수정:** 분산 락 또는 단일 스케줄러 인스턴스와 실행 기간 유니크 키를 적용한다.

### [RV-M2-02] 예약 배치의 분산 스케줄러 중복 방지는 행 단위 락에 의존

- **심각도:** MEDIUM
- **위치:** `ScheduledTransferRepository.findByIdForUpdate`, `ScheduledTransferService.executeOne`
- **위험 시나리오:** 행 락과 상태 재확인으로 이중 이체는 막지만 모든 인스턴스가 동일 도래 목록을 조회하고 순차 경쟁할 수 있어 락 대기와 부하가 발생할 수 있다.
- **권장 수정:** 배치 분할 또는 분산 작업 큐와 작업 소유권을 추가하고, 예약 행 락은 최종 중복 방어로 유지한다.

### [RV-M2-03] 예약 실패 상태 커밋과 감사 로그의 장애를 관찰 지표로 노출

- **심각도:** LOW
- **위치:** `ScheduledTransferService.markFailedSafely`
- **위험 시나리오:** FAILED 기록 중 일시 오류가 발생하면 PENDING을 유지하고 다음 주기 재시도하도록 잘 보완했지만 운영자 알림이 부족할 수 있다.
- **권장 수정:** 재시도 대기 건과 실패 상태 저장 오류를 메트릭/알림으로 노출한다.

## 강점

1. PIN 실패 카운트와 잠금은 별도 트랜잭션으로 본 거래 롤백과 분리된다.
2. 대사는 3대 불변식과 최대 100건 상세 상한을 함께 사용한다.
3. 예약 도래 건은 행 락, 상태 재확인, 내부 멱등키로 중복 이체를 차단한다.
4. 실행 실패는 원장 롤백과 FAILED 상태 커밋을 분리한다.
