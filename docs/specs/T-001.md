# T-001 상세 명세: 백엔드 프로젝트 초기화 및 DB 스키마(Flyway V1)

## 1. 목표
D-001, D-003, D-004([docs/DECISIONS.md](../DECISIONS.md)) 결정에 따라 Spring Boot 3.x (Java 17, Gradle) 백엔드 프로젝트(`backend/`)와 `docker-compose.yml`, Flyway V1 초기 스키마(8개 핵심 테이블) 및 JPA 엔티티/리포지토리 매핑을 구성한다.

## 2. 생성·수정 대상 파일/폴더
- `docker-compose.yml` (루트): PostgreSQL 16 (`postgres:16-alpine`, DB/User/Pass: `corebank`, 포트 `5432:5432`)
- `backend/`:
  - Gradle Wrapper (`gradlew`, `gradle/wrapper/...`) 및 `build.gradle`, `settings.gradle`
  - 패키지 루트: `com.corebank`
  - 의존성:
    - `spring-boot-starter-web`, `spring-boot-starter-data-jpa`, `spring-boot-starter-validation`, `spring-boot-starter-security`
    - `flyway-core`, `flyway-database-postgresql`, `org.postgresql:postgresql`
    - `io.jsonwebtoken:jjwt-api:0.12.6`, `jjwt-impl:0.12.6`, `jjwt-jackson:0.12.6`
    - 테스트용: `spring-boot-starter-test`, `spring-security-test`, `com.h2database:h2`
  - **QA 테스트 폴더(`tests/backend`) 연동 (필수)**:
    - QA는 `tests/` 폴더만 수정하므로 `backend/build.gradle`의 `sourceSets.test.java.srcDirs`에 `'src/test/java'`와 `'../tests/backend'`를 함께 등록한다.
    - 루트의 `tests/backend/` 아래에 컨텍스트 로드 확인용 기본 테스트(또는 패키지 디렉터리)를 두어 `cd backend && ./gradlew test` 실행 시 `tests/backend`가 함께 컴파일·실행되는지 검증한다.

## 3. Flyway V1 스키마 (`backend/src/main/resources/db/migration/V1__init_schema.sql`) 및 JPA 엔티티
모든 금액 컬럼은 `NUMERIC(19, 0)` (Java `BigDecimal`, scale 0)을 사용한다 (`float`/`double` 금지).

1. `users`
   - `id BIGSERIAL PRIMARY KEY`, `email VARCHAR(255) NOT NULL UNIQUE`, `password_hash VARCHAR(255) NOT NULL`, `name VARCHAR(100) NOT NULL`, `role VARCHAR(20) NOT NULL` (`USER`, `ADMIN`), `created_at TIMESTAMP NOT NULL`, `updated_at TIMESTAMP NOT NULL`
2. `accounts`
   - `id BIGSERIAL PRIMARY KEY`, `account_number VARCHAR(30) NOT NULL UNIQUE`, `user_id BIGINT REFERENCES users(id)` (시스템 시재 계좌는 NULL 허용), `is_system BOOLEAN NOT NULL DEFAULT FALSE`, `balance NUMERIC(19,0) NOT NULL DEFAULT 0`, `status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE'` (`ACTIVE`, `LOCKED`, `CLOSED`), `pin_hash VARCHAR(255) NOT NULL`, `pin_fail_count INT NOT NULL DEFAULT 0`, `per_tx_limit NUMERIC(19,0) NOT NULL DEFAULT 10000000`, `daily_limit NUMERIC(19,0) NOT NULL DEFAULT 50000000`, `version BIGINT NOT NULL DEFAULT 0`, `created_at TIMESTAMP NOT NULL`, `updated_at TIMESTAMP NOT NULL`
3. `transactions`
   - `id BIGSERIAL PRIMARY KEY`, `tx_type VARCHAR(20) NOT NULL` (`DEPOSIT`, `WITHDRAWAL`, `TRANSFER`), `status VARCHAR(20) NOT NULL` (`COMPLETED`, `FAILED`), `amount NUMERIC(19,0) NOT NULL CHECK (amount > 0)`, `from_account_id BIGINT REFERENCES accounts(id)`, `to_account_id BIGINT REFERENCES accounts(id)`, `idempotency_key VARCHAR(100) UNIQUE`, `description VARCHAR(255)`, `created_at TIMESTAMP NOT NULL`
4. `ledger_entries` (복식부기 분개 — Append-Only)
   - `id BIGSERIAL PRIMARY KEY`, `transaction_id BIGINT NOT NULL REFERENCES transactions(id)`, `account_id BIGINT NOT NULL REFERENCES accounts(id)`, `entry_type VARCHAR(10) NOT NULL` (`DEBIT`, `CREDIT`), `amount NUMERIC(19,0) NOT NULL CHECK (amount > 0)`, `balance_after NUMERIC(19,0) NOT NULL`, `created_at TIMESTAMP NOT NULL`
5. `idempotency_records`
   - `id BIGSERIAL PRIMARY KEY`, `idempotency_key VARCHAR(100) NOT NULL UNIQUE`, `user_id BIGINT NOT NULL`, `endpoint VARCHAR(100) NOT NULL`, `request_hash VARCHAR(128) NOT NULL`, `response_status INT NOT NULL`, `response_body TEXT NOT NULL`, `created_at TIMESTAMP NOT NULL`
6. `scheduled_transfers`
   - `id BIGSERIAL PRIMARY KEY`, `user_id BIGINT NOT NULL REFERENCES users(id)`, `from_account_id BIGINT NOT NULL REFERENCES accounts(id)`, `to_account_id BIGINT NOT NULL REFERENCES accounts(id)`, `amount NUMERIC(19,0) NOT NULL CHECK (amount > 0)`, `scheduled_at TIMESTAMP NOT NULL`, `status VARCHAR(20) NOT NULL` (`PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`, `CANCELED`), `failure_reason VARCHAR(255)`, `executed_transaction_id BIGINT REFERENCES transactions(id)`, `idempotency_key VARCHAR(100) NOT NULL UNIQUE`, `created_at TIMESTAMP NOT NULL`, `executed_at TIMESTAMP`
7. `reconciliation_runs`
   - `id BIGSERIAL PRIMARY KEY`, `trigger_type VARCHAR(20) NOT NULL` (`MANUAL`, `SCHEDULED`), `status VARCHAR(20) NOT NULL` (`PASSED`, `MISMATCH_FOUND`), `checked_accounts INT NOT NULL`, `checked_transactions INT NOT NULL`, `mismatch_count INT NOT NULL`, `details_json TEXT`, `executed_by BIGINT`, `executed_at TIMESTAMP NOT NULL`
8. `audit_logs` (감사 로그 — Append-Only)
   - `id BIGSERIAL PRIMARY KEY`, `actor_user_id BIGINT`, `action_type VARCHAR(50) NOT NULL`, `target_type VARCHAR(50) NOT NULL`, `target_id VARCHAR(100)`, `result VARCHAR(20) NOT NULL` (`SUCCESS`, `FAILURE`), `masked_summary TEXT NOT NULL`, `client_ip VARCHAR(64)`, `created_at TIMESTAMP NOT NULL`

## 4. 설정 및 완료 조건
- `application.yml`: PostgreSQL 기본 연결 (`localhost:5432/corebank`), `spring.jpa.hibernate.ddl-auto: validate`, `spring.flyway.enabled: true`
- `application-test.yml`: H2 (`MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;DEFAULT_NULL_ORDERING=HIGH`) + Flyway 활성화 + `ddl-auto: validate` 설정으로 로컬 Docker 기동 여부와 무관하게 `./gradlew test`에서 Flyway V1 스키마와 JPA 엔티티 매핑이 검증되도록 한다.
- **검증 명령**: `cd backend && ./gradlew test` 성공 확인.
- 완료 후 `docs/TASKS.md`의 `T-001` 상태를 `개발 완료`로 변경하고 `## 작업 기록`에 한 줄 요약을 추가한다.
