# T-002 상세 명세: 공통 기반 (에러 코드·예외 처리, 민감정보 마스킹, 감사 로그, 멱등성)

## 1. 목표
금융 도메인 품질 기준(금액/입력 검증, 민감정보 마스킹, 감사 로그, 중복 요청 방지)을 뒷받침하는 4가지 공통 모듈을 `backend/`에 구현한다.

## 2. 구현 항목 (`backend/src/main/java/com/corebank/...`)

### A. 표준 에러 코드 및 전역 예외 처리 (`common/exception`)
- `ErrorCode` (HTTP 상태코드 + 표준 코드 + 기본 메시지):
  - `INVALID_INPUT` (400), `INVALID_AMOUNT` (400), `SAME_ACCOUNT_TRANSFER` (400), `ACCOUNT_CLOSED` (400), `INSUFFICIENT_BALANCE` (400), `PER_TX_LIMIT_EXCEEDED` (400), `DAILY_LIMIT_EXCEEDED` (400)
  - `UNAUTHORIZED` (401), `INVALID_PIN` (401)
  - `FORBIDDEN_ACCOUNT_ACCESS` (403), `ACCOUNT_LOCKED` (403)
  - `USER_NOT_FOUND` (404), `ACCOUNT_NOT_FOUND` (404), `SCHEDULED_TRANSFER_NOT_FOUND` (404)
  - `DUPLICATE_EMAIL` (409), `IDEMPOTENCY_CONFLICT` (409)
  - `INTERNAL_ERROR` (500)
- `BusinessException` & `ApiErrorResponse(code, message, timestamp)`
- `GlobalExceptionHandler` (`@RestControllerAdvice`): 모든 예외를 표준 JSON 포맷으로 반환하며 내부 스택트레이스나 민감정보는 외부 응답에 노출하지 않는다.

### B. 민감정보 마스킹 유틸 (`common/util/MaskingUtil`)
- `maskAccountNumber(String accountNumber)`: 뒤 4자리만 남기고 중간 숫자 마스킹 (예: `110-123-456789` → `110-***-**6789`, `SYSTEM-VAULT`는 그대로 유지)
- `maskEmail(String email)`: `ho***@example.com` 형식
- `maskSensitiveText(String text)`: 로그/감사 요약 문자열에 포함된 `password`, `pin` 값이나 계좌번호 패턴을 마스킹 처리

### C. 감사 로그 서비스 (`audit/AuditLogService`)
- 모든 금전 거래 및 주요 보안 이벤트를 `audit_logs` 테이블에 기록한다.
- `maskedSummary` 저장 전 반드시 `MaskingUtil`을 거쳐 평문 비밀번호·PIN·전체 계좌번호가 저장되지 않도록 보장한다.
- 트랜잭션 전파 분리:
  - `logInTransaction(...)`: 성공 거래와 한 트랜잭션으로 묶여 커밋되는 감사 로그
  - `logIndependent(...)` (`@Transactional(propagation = Propagation.REQUIRES_NEW)`): PIN 오류, 로그인 실패, 잔액 부족 등 비즈니스 예외로 본 트랜잭션이 롤백되어도 감사 로그는 반드시 남도록 별도 트랜잭션으로 저장

### D. 멱등성 서비스 (`common/idempotency/IdempotencyService`)
- `idempotency_records` 테이블을 사용해 `(idempotencyKey, userId, endpoint, requestHash)`를 관리한다.
- 요청 본문(또는 핵심 파라미터)의 SHA-256 해시를 계산해 `requestHash`로 저장한다.
- 동일 `idempotencyKey` 재요청 시:
  - `userId`, `endpoint`, `requestHash`가 모두 일치하면 저장된 `responseStatus`와 `responseBody`를 반환(중복 실행 차단).
  - 하나라도 다르면 `BusinessException(ErrorCode.IDEMPOTENCY_CONFLICT)`(409)를 던진다.

## 3. 완료 조건
- 위 4개 모듈의 동작을 확인하는 핵심 단위/슬라이스 테스트(`MaskingUtil`, `IdempotencyService`, `AuditLogService`)가 `cd backend && ./gradlew test`에서 통과할 것.
- 완료 후 `docs/TASKS.md`의 `T-002` 상태를 `개발 완료`로 변경하고 `## 작업 기록`에 한 줄 요약을 남길 것.
