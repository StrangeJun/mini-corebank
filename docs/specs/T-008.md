# T-008 상세 명세: 계좌 비밀번호(PIN) 5회 오류 자동 잠금(`LOCKED`) 및 관리자 해제

## 1. 목표
출금·즉시 이체·예약 이체 등록 시 계좌 PIN 검증에서 **연속 5회 오류 시 계좌를 자동으로 `LOCKED`(거래정지) 상태로 전환**하고, 관리자(`ROLE_ADMIN`)가 잠금을 해제할 수 있는 API를 구현한다.

## 2. 상세 동작 (`com.corebank.account`)
1. **PIN 검증 서비스 (`AccountPinVerificationService` 또는 별도 `REQUIRES_NEW` 트랜잭션 메서드)**:
   - **핵심 주의사항**: PIN이 틀렸을 때 `BusinessException(ErrorCode.INVALID_PIN)`을 던지면 호출자의 본 거래 트랜잭션이 롤백된다. 따라서 **`pin_fail_count` 증가 및 5회 도달 시 `status = LOCKED` 전환과 감사 로그 기록은 반드시 `Propagation.REQUIRES_NEW` 트랜잭션에서 커밋된 뒤** 예외를 던져야 한다!
   - 검증 전 계좌 상태가 이미 `LOCKED`이면 즉시 `ACCOUNT_LOCKED`(403) 반환.
   - PIN 불일치 시:
     - `pin_fail_count`를 `+1` 증가시킨다 (`SELECT ... FOR UPDATE`로 동시 시도 안전 보장).
     - `pin_fail_count >= 5`가 되면 `account.status = AccountStatus.LOCKED`로 전환하고 `ACCOUNT_LOCKED` 감사 로그를 남긴다.
     - `PIN_FAIL` 감사 로그를 남긴다 (현재 실패 횟수 포함, 평문 PIN 절대 미포함).
     -5회 미만이면 `INVALID_PIN`(401), 5회 도달로 잠겼으면 `ACCOUNT_LOCKED`(403) 예외를 던진다.
   - PIN 일치 시:
     - 기존 `pin_fail_count > 0`이었다면 `0`으로 초기화한다.
2. **관리자 계좌 잠금 해제 API — `POST /api/admin/accounts/{accountId}/unlock`**
   - 권한: `ROLE_ADMIN` 전용 (일반 사용자 접근 시 `403`).
   - 동작:
     - 계좌 상태를 `ACTIVE`로 변경하고 `pin_fail_count = 0`으로 초기화한다.
     - `ACCOUNT_UNLOCKED` 감사 로그 기록.
   - 응답 (`200 OK`): `{ "id": 1, "maskedAccountNumber": "110-***-**6789", "status": "ACTIVE", "pinFailCount": 0 }`

## 3. 완료 조건
- PIN 1~4회 실패 시 `pin_fail_count` 누적 및 성공 시 `0` 초기화, 5회 연속 실패 시 본 거래 롤백과 무관하게 `status = LOCKED` 확정 및 이후 모든 거래 차단, 관리자 잠금 해제 후 정상 거래 재개 테스트가 `cd backend && ./gradlew test`에서 통과할 것.
- 완료 후 `docs/TASKS.md`의 `T-008` 상태를 `개발 완료`로 바꾸고 `## 작업 기록`에 한 줄 요약을 남길 것.
