# T-010 상세 명세: 예약 이체(Scheduled Transfer) 등록·조회·취소 및 멱등 스케줄러

## 1. 목표
지정된 시각(`scheduledAt`)에 실행되는 예약 이체를 등록(등록 시 PIN 검증)·조회·취소하고, 스케줄러가 도래한 예약 이체를 중복 없이 멱등하게 실행하며 실행 시점의 잔액/한도/계좌상태를 재검증하여 성공(`COMPLETED`) 또는 실패(`FAILED` + `failureReason`)를 기록한다.

## 2. API 및 스케줄러 명세 (`com.corebank.scheduled`)

### A. 예약 이체 등록 — `POST /api/scheduled-transfers` (헤더: `Idempotency-Key` 필수)
- 요청: `{ "fromAccountId": 1, "toAccountNumber": "110-...", "amount": 30000, "pin": "1234", "scheduledAt": "2026-11-25T10:00:00", "description": "적금 자동이체" }`
- 검증:
  - 본인 출금 계좌 소유권 확인 (`FORBIDDEN_ACCOUNT_ACCESS` 403)
  - 출금/입금 계좌 존재 및 `ACTIVE` 상태 확인, 동일 계좌 여부(`SAME_ACCOUNT_TRANSFER` 400)
  - 금액 양수·정수(`BigDecimal` scale 0) 및 `amount <= fromAccount.perTxLimit` 확인
  - **등록 시점에 출금 계좌 PIN 검증** (T-008의 5회 오류 잠금 정책 동일 적용)
  - `IdempotencyService`를 통한 중복 등록 방지
- 저장: `status = "PENDING"`, `scheduled_transfers` 저장 및 감사 로그 `SCHEDULED_TRANSFER_CREATE` 기록.
- 응답 (`201 Created`): `{ "id": 1, "fromAccountId": 1, "toAccountNumberMasked": "110-***-**...", "amount": 30000, "scheduledAt": "...", "status": "PENDING", "createdAt": "..." }`

### B. 내 예약 이체 목록 조회 — `GET /api/scheduled-transfers`
- 현재 로그인 사용자의 예약 이체 목록을 최신순 반환 (`status` 필터 지원).

### C. 예약 이체 취소 — `POST /api/scheduled-transfers/{id}/cancel`
- 본인 예약 이체만 가능(타인 `403`).
- `status == "PENDING"` 일 때만 `"CANCELED"`로 변경 가능 (이미 `COMPLETED`/`FAILED`/`CANCELED` 이면 `INVALID_INPUT` 400).
- 감사 로그 `SCHEDULED_TRANSFER_CANCEL` 기록.

### D. 도래 건 실행 엔진 & 스케줄러 (`executeDueTransfers()`)
- `@Scheduled(fixedDelayString = "${corebank.scheduler.transfer-delay-ms:30000}")` 및 관리자/테스트 수동 트리거 엔드포인트 `POST /api/admin/scheduled-transfers/execute-due` (`ROLE_ADMIN`) 제공.
- `status = 'PENDING'` 이고 `scheduled_at <= NOW()` 인 건들을 조회하여 건별 독립 트랜잭션으로 처리:
  - 동시 스케줄러 중복 실행 방지를 위해 해당 `scheduled_transfer` 행을 비관적 락(`PESSIMISTIC_WRITE`)으로 잠그고 `status == 'PENDING'`인지 재확인.
  - 내부 이체 실행 시 고유 멱등키(`"SCHED-TX-" + scheduledTransfer.id`)로 이체 원장 로직을 호출해 이중 이체를 원천 차단.
  - **성공 시**: `status = "COMPLETED"`, `executed_transaction_id = tx.id`, `executed_at = NOW()`, 감사 로그 `SCHEDULED_TRANSFER_EXEC` (`SUCCESS`).
  - **실패 시**(실행 시점 잔액 부족, 계좌 잠금/해지, 1일 한도 초과 등): 이체 원장 변경은 롤백하되 예약 이체 상태는 `status = "FAILED"`, `failure_reason = e.getErrorCode().name()`, `executed_at = NOW()`로 기록하고 감사 로그 `SCHEDULED_TRANSFER_EXEC` (`FAILURE`)를 남긴다.

## 3. 완료 조건
- 예약 이체 등록(PIN 검증)·취소, 도래 건 정상 실행 시 원장 2줄 분개 생성 및 `COMPLETED` 전환, 실행 시점 잔액 부족/계좌 잠금 시 `FAILED` + `failure_reason` 기록, 동일 도래 건 2회 실행 시 중복 이체 없음 테스트가 `cd backend && ./gradlew test`에서 통과할 것.
- 완료 후 `docs/TASKS.md`의 `T-010` 상태를 `개발 완료`로 바꾸고 `## 작업 기록`에 한 줄 요약을 남길 것.
