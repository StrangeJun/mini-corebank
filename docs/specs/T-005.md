# T-005 상세 명세: 복식부기 원장 기반 입금·출금·즉시 이체 (동시성·데드락 방지·한도·멱등성)

## 1. 목표
1금융권 코어뱅킹의 핵심인 **복식부기 원장(Double-Entry Ledger) 분개**, **계좌 ID 오름차순 비관적 락(`PESSIMISTIC_WRITE`) 데드락 방지**, **1회/1일 한도 검증**, **`Idempotency-Key` 중복 요청 차단**을 갖춘 입금·출금·즉시 이체를 구현한다.

## 2. 공통 금융 도메인 불변 규칙 (필수 준수)
1. **금액 검증**:
   - `BigDecimal`만 사용하며, `amount == null || amount.scale() > 0 || amount.compareTo(BigDecimal.ZERO) <= 0` 이면 `INVALID_AMOUNT`(400) 발생.
2. **계좌 상태 & 소유권 검증**:
   - `ACTIVE` 상태가 아닌 계좌(`LOCKED` → `ACCOUNT_LOCKED` 403, `CLOSED` → `ACCOUNT_CLOSED` 400)는 입·출금·이체 불가.
   - 출금/이체의 출금 계좌(`fromAccount`)는 반드시 현재 로그인 사용자 소유여야 함 (`userId != currentUserId` 이면 `FORBIDDEN_ACCOUNT_ACCESS` 403).
3. **비관적 락 & 데드락 방지**:
   - 잔액을 변경하는 모든 거래는 `@Transactional` 안에서 대상 계좌(고객 계좌 및 `SYSTEM-VAULT`)를 **계좌 `id` 오름차순으로 정렬하여 `SELECT ... FOR UPDATE`(`LockModeType.PESSIMISTIC_WRITE`)로 잠근 뒤** 처리한다. (A→B 이체와 B→A 이체가 동시에 들어와도 데드락 원천 차단)
4. **복식부기 2줄 분개 (`ledger_entries`)**:
   - 모든 거래(`transactions`)는 반드시 **2개의 `ledger_entries`(`DEBIT` 1건, `CREDIT` 1건)**를 생성한다.
   - **입금(`DEPOSIT`)**:
     - `fromAccount` = `SYSTEM-VAULT` (`DEBIT`, 잔액 `-amount`), `toAccount` = 고객 계좌 (`CREDIT`, 잔액 `+amount`)
   - **출금(`WITHDRAWAL`)**:
     - `fromAccount` = 고객 계좌 (`DEBIT`, 잔액 `-amount`), `toAccount` = `SYSTEM-VAULT` (`CREDIT`, 잔액 `+amount`)
   - **이체(`TRANSFER`)**:
     - `fromAccount` = 출금 계좌 (`DEBIT`, 잔액 `-amount`), `toAccount` = 입금 계좌 (`CREDIT`, 잔액 `+amount`)
   - 각 `ledger_entry`의 `balance_after`에는 해당 분개 반영 직후의 계좌 잔액 스냅샷을 정확히 기록한다.
5. **잔액 및 한도 검증**:
   - 출금/이체 시 `fromAccount.balance < amount` 이면 `INSUFFICIENT_BALANCE`(400).
   - 출금/이체 시 `amount > fromAccount.perTxLimit` 이면 `PER_TX_LIMIT_EXCEEDED`(400).
   - 출금/이체 시 당일(00:00:00 ~ 23:59:59) 해당 출금 계좌에서 완료된 출금+이체 누적액 + `amount > fromAccount.dailyLimit` 이면 `DAILY_LIMIT_EXCEEDED`(400).
6. **멱등성 (`Idempotency-Key` 헤더 필수)**:
   - `Idempotency-Key` 헤더가 없거나 공백이면 `INVALID_INPUT`(400).
   - `IdempotencyService`를 통해 동일 키 + 동일 요청이면 기존 결과를 반환하고, 동일 키 + 다른 요청 본문이면 `IDEMPOTENCY_CONFLICT`(409)를 반환한다.
7. **감사 로그**:
   - 성공 시 `logInTransaction`, 실패(잔액 부족, 한도 초과, 계좌 잠금 등) 시 `logIndependent`로 감사 로그를 남기며 계좌번호는 마스킹하고 PIN은 절대 남기지 않는다.

## 3. API 명세 (`com.corebank.transaction`)
1. `POST /api/transactions/deposit` (헤더: `Idempotency-Key`)
   - 요청: `{ "accountId": 1, "amount": 50000, "description": "급여 입금" }`
   - 응답 (`200 OK`): `{ "transactionId": 10, "txType": "DEPOSIT", "amount": 50000, "balanceAfter": 50000, "description": "급여 입금", "createdAt": "..." }`
2. `POST /api/transactions/withdraw` (헤더: `Idempotency-Key`)
   - 요청: `{ "accountId": 1, "amount": 10000, "pin": "1234", "description": "현금 출금" }`
   - PIN 검증 포함(불일치 시 `INVALID_PIN` 401; 5회 잠금 로직은 T-008에서 고도화하되 기본 PIN 일치 체크 수행).
   - 응답 (`200 OK`): `{ "transactionId": 11, "txType": "WITHDRAWAL", "amount": 10000, "balanceAfter": 40000, "description": "현금 출금", "createdAt": "..." }`
3. `POST /api/transactions/transfer` (헤더: `Idempotency-Key`)
   - 요청: `{ "fromAccountId": 1, "toAccountAccountNumber": "110-...", "amount": 20000, "pin": "1234", "description": "월세 이체" }` (또는 `toAccountId` / `toAccountNumber` 모두 지원: `toAccountNumber` 기준 조회 권장, `toAccountId`가 오면 그것도 허용)
   - 출금 계좌와 입금 계좌가 같으면 `SAME_ACCOUNT_TRANSFER`(400).
   - 응답 (`200 OK`): `{ "transactionId": 12, "txType": "TRANSFER", "amount": 20000, "fromAccountId": 1, "toAccountNumberMasked": "110-***-**...", "balanceAfter": 20000, "description": "월세 이체", "createdAt": "..." }`
