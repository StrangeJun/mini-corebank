# T-011 상세 명세: 마일스톤 2 QA (PIN 5회 오류 잠금/해제, 3대 불변식 정합성 대사, 예약 이체)

## 1. 목표
마일스톤 2(`T-008` ~ `T-010`)의 1금융권 심화 기능이 요구사항과 금융 도메인 품질 기준을 완벽히 만족하는지 `tests/backend/`에 QA 테스트를 추가하고 `./gradlew test`로 검증한다.

## 2. 규칙 (`docs/roles/qa.md` 엄수)
- **`tests/`, `docs/`, `README.md` 만 수정한다.** `backend/src/main` 기능 코드는 절대 수정하지 않는다.
- 버그 발견 시 직접 고치지 말고 재현 방법과 함께 `docs/TASKS.md`에 보고한다.

## 3. 필수 검증 테스트 항목 (`tests/backend/com/corebank/...`)
1. **PIN 5회 오류 잠금 & 해제 (`T-008`)**:
   - 4회 연속 PIN 오류 후 5번째 올바른 PIN 입력 시 정상 출금/이체 및 `pin_fail_count == 0` 초기화 확인
   - 5회 연속 PIN 오류 시 본 거래는 실패(잔액 불변)하되 계좌 상태는 `LOCKED`로 영구 커밋되는지 확인
   - `LOCKED` 계좌에서 올바른 PIN으로 출금/이체 시도 시 `403 ACCOUNT_LOCKED`로 차단되는지 확인
   - 일반 사용자(`USER`)가 잠금 해제 API 호출 시 `403` 차단, 관리자(`ADMIN`)가 잠금 해제 후 정상 이체 가능한지 확인
2. **원장-잔액 정합성 대사 (`T-009`)**:
   - 복합 거래(입금·출금·이체·예약이체) 수행 후 대사 실행 시 `status == PASSED`, `mismatchCount == 0` 확인
   - DB의 특정 계좌 `balance`를 인위적으로 변경한 뒤 대사 실행 시 `status == MISMATCH_FOUND` 및 불일치 상세가 정확히 기록되는지 확인
3. **예약 이체 (`T-010`)**:
   - 잘못된 PIN으로 예약 이체 등록 시 거부 및 `pin_fail_count` 증가 확인
   - 도래한 예약 이체 배치 실행 시 출금/입금 잔액 변동, 복식부기 2줄 분개 생성, `COMPLETED` 상태 전환 확인
   - 실행 시점에 출금 계좌 잔액이 부족하거나 계좌가 `LOCKED` 상태일 때 `status == FAILED` 및 `failureReason`(`INSUFFICIENT_BALANCE`, `ACCOUNT_LOCKED`) 기록 확인
   - 이미 `COMPLETED` 또는 `CANCELED`된 예약 이체가 배치 재실행 시 절대 중복 이체되지 않는지 확인

## 4. 완료 조건
- `cd backend && ./gradlew test`를 실행하여 전체 테스트 통과를 확인한다.
- `docs/TASKS.md`의 `T-011` 상태를 갱신하고 `## 작업 기록`에 한 줄 요약을 남긴다:
  `- T-011 QA: 테스트 <n>개, 통과 <n> / 실패 <n> / 발견한 문제: <요약 또는 없음>`
