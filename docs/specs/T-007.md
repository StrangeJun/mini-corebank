# T-007 상세 명세: 마일스톤 1 QA (코어 원장·입출금·이체·동시성·멱등성·권한·경계값·마스킹)

## 1. 목표
마일스톤 1(`T-001` ~ `T-006`)의 구현이 금융 도메인 품질 기준(`docs/roles/qa.md`, `docs/TEST_PLAN.md`)을 모두 만족하는지 `tests/backend/`에 통합/동시성 테스트를 작성하고 실제로 `./gradlew test`를 실행해 검증한다.

## 2. 규칙 (`docs/roles/qa.md` 엄수)
- **`tests/`, `docs/`, `README.md` 만 수정한다.** `backend/src/main` 등 기능 코드는 절대 수정하지 않는다.
- 버그를 발견하면 직접 고치지 말고 재현 방법(실패 테스트 케이스 및 원인)과 함께 `docs/TASKS.md`에 보고한다.

## 3. 필수 검증 테스트 항목 (`tests/backend/com/corebank/...`)
1. **경계값 & 금액 검증**:
   - 0원, 음수(`-1000`), 소수점(`100.5`) 입금·출금·이체 시 `400 INVALID_AMOUNT` 차단 확인
   - 잔액 부족 출금·이체 시 `400 INSUFFICIENT_BALANCE` 및 잔액 불변 확인
   - 1회 이체 한도 초과(`PER_TX_LIMIT_EXCEEDED`), 당일 누적 이체 한도 초과(`DAILY_LIMIT_EXCEEDED`) 차단 확인
   - 동일 계좌 간 이체(`SAME_ACCOUNT_TRANSFER`), 해지 계좌(`ACCOUNT_CLOSED`) 거래 차단 확인
2. **복식부기 원장 정합성**:
   - 입금·출금·이체 시 `ledger_entries`에 `DEBIT` 1건, `CREDIT` 1건(합계 일치)이 기록되고 `balance_after`가 정확히 일치하는지 확인
   - 전체 계좌(`고객 계좌들 + SYSTEM-VAULT`) 잔액의 합이 항상 `0`(`Zero-Sum`)인지 확인
3. **멱등성 (`Idempotency-Key`)**:
   - 동일 `Idempotency-Key` + 동일 본문으로 입금/출금/이체를 2번 요청 시 첫 번째와 동일한 응답이 반환되고 실제 잔액 차감·원장 분개는 딱 1번만 일어나는지 확인
   - 동일 `Idempotency-Key` + 다른 금액으로 재요청 시 `409 IDEMPOTENCY_CONFLICT` 반환 확인
4. **동시성 & 데드락 방지**:
   - 잔액 100,000원 계좌에서 30,000원 출금 요청 10개를 멀티스레드(`ExecutorService` + `CountDownLatch`)로 동시에 보낼 때 정확히 3건만 성공하고 최종 잔액이 10,000원인지 확인
   - 계좌 A(100,000원) ↔ 계좌 B(100,000원) 간 상호 교차 이체(A→B 10,000원 5건, B→A 10,000원 5건)를 동시에 실행할 때 데드락 없이 모두 완료되고 최종 잔액 합계가 200,000원으로 보존되는지 확인
5. **권한 & 민감정보 마스킹 & 감사 로그**:
   - 사용자 A가 사용자 B의 계좌 조회·출금·이체·거래내역 조회·해지 시도 시 `403 FORBIDDEN_ACCOUNT_ACCESS` 확인
   - 일반 사용자가 `/api/admin/audit-logs` 호출 시 `403` 차단 확인
   - 거래 성공 및 실패(잔액 부족, PIN 오류 등) 시 `audit_logs`에 기록이 남고, `masked_summary`에 평문 PIN·비밀번호·원본 계좌번호 전체가 노출되지 않는지 확인

- `docs/TASKS.md`의 `T-007` 상태를 갱신하고 `## 작업 기록`에 아래 형식으로 한 줄을 남긴다:
