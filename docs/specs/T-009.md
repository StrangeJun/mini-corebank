# T-009 상세 명세: 원장-잔액 정합성 대사(Reconciliation) 및 3대 불변식 검증

## 1. 목표
1금융권 코어뱅킹의 핵심 운영·감사 기능인 **원장-잔액 정합성 대사(Reconciliation)**를 구현하여 복식부기 3대 불변식을 검증하고 대사 실행 이력을 `reconciliation_runs`에 저장·조회한다.

## 2. 3대 대사 불변식 (`com.corebank.reconciliation`)
대사 실행 시 아래 3가지를 모두 검사하고, 불일치 항목이 하나라도 있으면 상세 내역(`details_json`)에 기록한다:
1. **불변식 1 — 거래별 차변/대변 일치 (`TX_BALANCE_MISMATCH`)**:
   - 완료(`COMPLETED`) 상태인 모든 `transactions`에 대해, 연결된 `ledger_entries`의 `SUM(CREDIT amount) == SUM(DEBIT amount) == transaction.amount` 인지 검증.
2. **불변식 2 — 계좌별 잔액-원장 합계 일치 (`ACCOUNT_LEDGER_MISMATCH`)**:
   - 모든 계좌(`accounts`, 고객 계좌 및 `SYSTEM-VAULT` 포함)에 대해 `account.balance == SUM(CREDIT.amount) - SUM(DEBIT.amount)` 인지 검증.
3. **불변식 3 — 전체 원장 제로섬 일치 (`ZERO_SUM_MISMATCH`)**:
   - 전체 계좌(`고객 계좌 + SYSTEM-VAULT`)의 `SUM(accounts.balance) == 0` 이고, 전체 분개의 `SUM(CREDIT.amount) == SUM(DEBIT.amount)` 인지 검증.

## 3. API 및 스케줄러 명세
1. **수동 대사 실행 API — `POST /api/admin/reconciliations/run`** (`ROLE_ADMIN` 전용)
   - 요청 본문 없음 (또는 선택 메모).
   - 동작:
     - 3대 불변식을 전수 검사하여 `mismatchCount == 0` 이면 `status = "PASSED"`, 1건 이상이면 `status = "MISMATCH_FOUND"`.
     - 결과를 `reconciliation_runs` 테이블에 저장 (`trigger_type = "MANUAL"`, `checked_accounts`, `checked_transactions`, `mismatch_count`, `details_json`, `executed_by = currentUserId`, `executed_at`).
     - 감사 로그 `RECONCILIATION_RUN` 기록.
   - 응답 (`200 OK`): `{ "id": 1, "triggerType": "MANUAL", "status": "PASSED", "checkedAccounts": 5, "checkedTransactions": 12, "mismatchCount": 0, "details": [], "executedAt": "..." }`
2. **대사 이력 목록/상세 조회 API**
   - `GET /api/admin/reconciliations` (`ROLE_ADMIN` 전용, 최신순 목록 조회)
   - `GET /api/admin/reconciliations/{id}` (`ROLE_ADMIN` 전용, 상세 조회)
3. **정기 대사 스케줄러**
   - `@Scheduled` 배치 진입점(`runScheduledReconciliation()`, `trigger_type = "SCHEDULED"`)을 제공한다.

## 4. 완료 조건
