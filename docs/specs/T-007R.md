## 2. 산출물 1 — 코드 리뷰 보고서 (`docs/reviews/M1-review.md`)

`backend/src/main/java/com/corebank/**`의 실제 코드를 읽고 금융 도메인 무결성, 트랜잭션/락 동시성, 멱등성 경합, 보안/JWT/마스킹, 쿼리 성능(N+1, 인덱스), 예외 처리 관점에서 정밀 검토한다.

### 작성 형식
1. **전체 총평 및 요약 통계**: 심각도별 건수 (`CRITICAL: n, HIGH: n, MEDIUM: n, LOW: n`)
2. **발견된 이슈 목록** (각 항목마다 아래 표/구조로 작성):
   - **ID & 제목**: 예: `[RV-M1-01] ...`
   - **심각도**: `CRITICAL` (데이터 부정합·금전 손실·보안 취약점) / `HIGH` (동시성 경합·기능 버그·트랜잭션 누수) / `MEDIUM` (성능·인덱스·엣지 케이스·코드 구조) / `LOW` (네이밍·가독성·사소한 개선)
   - **위치**: 파일 경로 및 라인 번호
   - **문제점 및 재현/위험 시나리오**: 왜 문제가 되는지 구체적 시나리오 설명
   - **권장 수정 방안**: Claude가 어떻게 고쳐야 하는지 구체적 코드/설계 방향 제시
3. **잘 구현된 설계 포인트 (Strengths)**: 3~5가지 요약

## 3. 산출물 2 — 한눈에 보는 마일스톤 1 학습 자료 (`docs/study/M1-core-ledger.md`)

오너가 이 문서 하나만 읽고 코드를 열면 **전체 흐름이 머릿속에 그림처럼 그려지도록** 시각적이고 체계적으로 작성한다 (`shower` 스킬 원칙: 처음 보는 사람도 단번에 이해할 수 있는 구조).

### 필수 포함 구성
1. **한눈에 보는 전체 아키텍처 & 패키지 지도**
   - Mermaid `flowchart LR` 또는 `flowchart TD`로 요청(`Controller`) → 보안 필터(`JwtAuthenticationFilter`) → 멱등성(`IdempotencyService`) → 비즈니스/락(`TransactionService`) → 원장/계좌(`Repository`) → 감사 로그(`AuditLogService`) 흐름 시각화
   - 패키지별 핵심 클래스 역할 요약 표 (`어느 파일이 무슨 일을 하는가`)
2. **핵심 원리 ① — 복식부기 원장(Double-Entry Ledger)과 `SYSTEM-VAULT` Zero-Sum**
   - 입금·출금·이체 시 각각 어느 계좌에 `DEBIT`(-)/`CREDIT`(+)이 찍히는지 표와 Mermaid 다이어그램으로 비교
   - 왜 외부 입출금에 `SYSTEM-VAULT`(시재 계좌)를 쓰면 `전체 계좌 잔액 합 == 0`이 유지되는지 직관적 예시(숫자 예시 포함)
   - `TransactionService.java`의 핵심 코드 블록 발췌 및 라인별 해설
3. **핵심 원리 ② — 동시성 제어와 데드락 방지 (`id` 오름차순 `PESSIMISTIC_WRITE`)**
   - 만약 락 순서를 정렬하지 않았을 때 A→B 이체와 B→A 이체가 어떻게 데드락(교착 상태)에 빠지는지 vs **계좌 ID 오름차순 정렬 잠금**이 어떻게 데드락을 원천 차단하는지 Mermaid `sequenceDiagram` 비교
   - 왜 잠금 전에 엔티티를 미리 영속성 컨텍스트(1차 캐시)에 로드하면 안 되는지(Stale read 방지) 코드 해설
4. **핵심 원리 ③ — 멱등성(`Idempotency-Key`)과 SHA-256 요청 해시**
   - 네트워크 타임아웃 재시도 시 이중 이체를 막는 2단계 체크(잠금 전 1차 조회 → 락 획득 후 2차 조회/저장) 흐름도
   - 왜 요청 해시(SHA-256)에서 PIN을 제외했는지(레인보우 테이블 역산 방지 보안 설계) 해설
5. **핵심 원리 ④ — 트랜잭션 전파 분리(`REQUIRED` vs `REQUIRES_NEW`)와 감사 로그·마스킹**
   - 잔액 부족이나 PIN 오류로 본 거래(`@Transactional`)가 롤백되어도 왜 `AuditLogService.logIndependent`(`REQUIRES_NEW`)는 DB에 살아남는지 Mermaid 다이어그램으로 설명
6. **효율적인 코드 공부 순서 (30분 완주 로드맵)**
   - 1단계(스키마/도메인) → 2단계(공통/멱등/감사) → 3단계(인증/시드) → 4단계(계좌/복식부기 이체) → 5단계(동시성 테스트) 순으로 읽을 파일과 핵심 포인트 안내
7. **1금융권 백엔드 기술 면접 단골 Q&A 6선**
   - 이 프로젝트 코드를 근거로 면접관에게 답변할 수 있는 질문과 모범 답변(두괄식)
